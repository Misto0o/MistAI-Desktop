# CLAUDE.md

Guidance for Claude Code (claude.ai/code) when working in this repository.

MistAI is a Windows-only (10/11, 64-bit) voice/text desktop assistant: a pywebview UI over a Python agent that controls the desktop (pywin32/pywinauto/UIA), a Playwright Firefox browser, and the shell. It depends on Win32 APIs, so there is no macOS/Linux path.

## Rules

- **Design philosophy:** MistAI is a general reasoning agent, not a collection of hardcoded per-task functions. Don't add task-specific actions or shortcuts to fix bad behavior. Improve planning, prompting, context, and model choice instead.
- **Never disable or bypass SSL/TLS verification.** If a TLS error appears, report it.
- **Never print, log, or send secret values** (`.env` keys, cookies, tokens), not even in tool output. Report names or lengths only.
- **Don't `git commit` or push unless asked.** Don't delete files; move candidates to a quarantine folder outside the repo.
- **Don't hardcode drive letters or user paths.** The repo may live on `E:\` or `D:\`.
- **Stub mode by default.** Real-backend or live-desktop runs only when explicitly asked (see Harness).
- **Keep the system prompt lean.** Merge new rules into existing ones and tighten wording instead of only appending.

## Commands

```bash
pip install -r requirements.txt
python -m playwright install firefox
python assistant.py                      # run the app (entry point is assistant.py)

python -m pytest -q                      # all tests (what CI runs; ~1720 tests)
python -m pytest tests/test_planner.py::test_name -q   # single test
python -m pytest -q -k test_name         # by name, wherever it lives

python -m compileall -q core ui tools assistant.py               # CI sanity check
python -c "import core.agent, core.api, core.executor, core.planner"

# Release build (CI does this on a v* tag; output is dist/MistAI.exe)
$env:PLAYWRIGHT_BROWSERS_PATH = "0"; python -m PyInstaller MistAI.spec --clean --noconfirm
```

- `MistAI.spec` requires `MistAI_OCREngine/Tesseract-OCR/` (bundled Tesseract) and bundles Playwright's Firefox, so set `PLAYWRIGHT_BROWSERS_PATH=0` before `playwright install` too.
- Secrets live in `.env` next to `assistant.py`: `MISTAI_API_KEY`, `COHERE_API_KEY`. `MISTAI_USE_BACKEND` toggles backend mode. `.env` is gitignored.
- `tests/conftest.py` puts the repo root on `sys.path`. Tests monkeypatch `time.sleep`, `threading.Thread`, and similar, so no real desktop or network is used.
- Tests are 12 files by area (orb, voice, confirmations, privacy, agent, screen, browser, windows, planner, memory, harness, api), each with a SECTION INDEX; a section is one former test file. Clashing helpers carry a section prefix (`_wake_word_audio`); sections with an autouse fixture (or a clashing test name) are classes (`tests/test_orb.py::TestOrbMotion::test_x`). Put new tests in the section of their area.
- Native crashes: `config.enable_crash_log()` (first line of `assistant.py` `main()`, and `tools/run_scenarios.py`'s `__main__` block only, never `main()`, which tests call) points faulthandler for every thread at `~/MistAI/logs/crash.log` (append, one handle kept open; frames only; works frozen; never raises).
- `MISTAI_DB_PATH` overrides the SQLite path for memory, tool stats, task store, and task memory (used by the harness so it never touches the real database).
- Logs are content-free unless `MISTAI_VERBOSE_LOGS=1` (`config.verbose_logs()`, read at call time): thinking, heard words, typed text, task text, plan names, click queries, OCR/UIA/vision words, window titles, paths and failure details print as lengths, exception types or fixed labels; any new console text needs the flag too (`tests/test_privacy.py` (PRIVACY CANARIES section) pins it). The flag is ignored in built apps (`sys.frozen`). Skim logs before sharing either way.
- Other settings (env, read at call time): `MISTAI_VOICE_DIAG=1` numbers-only `[VoiceDiag]` line per listen; `MISTAI_CONFIRM_LISTEN` = `shared` (default) | `ptt` | `lead` set-up of confirmation/ask_user listens (A/B); `MISTAI_CONFIRM_REMINIMIZE` (default on) re-minimizes MistAI after a confirmation; `MISTAI_SKIP_VERIFIED_READ` (default on) makes the read after a verified `open_app`/`switch_app` title + Open apps only; `MISTAI_VISION_Y_NUDGE` (default 30) px added to vision clicks with y < 80; `MISTAI_TASK_ACK` (default on) spoken "On it." for voice tasks; `MISTAI_NARRATION` = `milestones` (default) | `off`; `MISTAI_HISTORY_HOURS` (default 24, min 1) conversation retention; `MISTAI_CHAT_TIMEOUT` (default 5, 1-30) seconds for the router call; `MISTAI_SINGLE_SHOT` (default off) the router also answers `"single"`, and only an explicit `true` for that same message skips the planning call (logged `[Conversation] single deliverable: yes|no`); `MISTAI_ROUTER_VIA_AGENT` (default off) sends router and planner calls in the agent request form (`"mode": "agent"`, `system`, `messages`; the router's system prompt is one voice line, `planner.ROUTER_SYSTEM`) with the same prompts and schemas, failing closed as before; `MISTAI_UIA_FIRST` (default on) and `MISTAI_BATCH_STEPS` (default on), see Agent behavior; `MISTAI_WINDOW_EVENTS` (default on; tests and rollback only) the WinEvent hook below; `MISTAI_SEARCH_ENGINE` = `duckduckgo` (default: browser_search tries DuckDuckGo's normal page, then its HTML endpoint on a block or empty page, then fails with "the search was blocked"; no other engine, no escalation) | `google` (Google, then DuckDuckGo HTML).

## Architecture

**Entry and UI.** `assistant.py` creates `core.api.Api` and passes it to pywebview as `js_api`. The UI is one HTML string in `ui/html.py` that calls `Api` methods from JS. The orb shows one state (`orbState`: push-to-talk listening > speaking, from `is_agent_busy().speaking` > thinking, a running task > idle) as `data-state` on `#orb-wrap`; CSS only, static under `prefers-reduced-motion`. Settings > Floating orb (off by default, `user_profile` `floating_orb`) opens `core/floating_orb.py`: a small frameless always-on-top window (`ORB_HTML`, a flat frosted disc tinted by `config.ORB_TINT`; js_api `OrbBridge`: `orb_state()` and `talk("start"|"stop"|"toggle")`, which maps a hold (start on 280 ms still, send on release), a tap (toggle) and a drag (> 6 px, never talk) onto `Api.push_to_talk`) that stays visible while the main window is minimized. Once shown it is placed in physical px inside the primary monitor's work area (`place()`: the big size x scale, 16 px x scale from the right and bottom) and cut round with ctypes `gdi32.CreateEllipticRgn` + `SetWindowRgn` (pywin32 has no `CreateEllipticRgn`); it logs `[FloatingOrb] at x,y size w,h monitor-scale s` and failed calls by name and error code. It is excluded from capture (`WDA_EXCLUDEFROMCAPTURE`, black box before Windows 10 2004), masked from OCR by handle (`extra_own_windows_fn`), never activates (`WS_EX_NOACTIVATE`, verified on show, plus a `WM_MOUSEACTIVATE` -> `MA_NOACTIVATE` subclass), has no title (title lookups skip it), lives in MistAI's PID (Open apps skips it), and input is refused while it is in front. A 4 Hz control thread (`FloatingOrb.tick`) resizes it about its center with a cancellable `Tween` (SetWindowPos + a new circle per frame): big idle/listening, medium thinking/speaking, small docked: `config.orb_sizes()`, `MISTAI_ORB_SIZES="big,med,small"` read at call time (default 82,70,28; bad input = default), logical px x monitor scale; dragging it at home moves home. Windows are created with `min_size=(1, 1)` (pywebview's default (200, 100) clamps every resize), the actual rect is read back and logged (`requested W,H actual W,H`) and the region cut from it; the orb's window and page background is the disc's rim colour (`config.orb_background()`). `hide_from_taskbar` sets WS_EX_TOOLWINDOW|NOACTIVATE, clears APPWINDOW and hides + re-shows the window (the taskbar only re-reads styles on show). Moves are a retargetable damped spring (`core/floating_orb.py`, closed form, position from `perf_counter` only; `MISTAI_ORB_MOTION` = lively (default, small capped overshoot, a lean-back before long flights) | calm (critically damped)), paced per refresh by `FramePacer` (DwmFlush, else a high-resolution waitable timer, else timeBeginPeriod + sleep) on an above-normal thread with a 1 ms switch interval; one `SetWindowPos(SWP_FRAME)` per frame (ASYNCWINDOWPOS, no logging or locks); size changes are short timed steps and the region is recut only then; `orb_layout.flight_plan` resizes before take-off or after landing, never mid-flight; a goal that moves in flight retargets (`Tween.retarget`); a dock's dwell starts at the landing; Windows animation effects off (SPI_GETCLIENTAREAANIMATION) = jump. `MISTAI_ORB_FRAME_STATS=1` (ignored when frozen) logs one numbers-only `frame stats` line per flight. `MISTAI_ORB_DEBUG_CAPTURE=1` (ignored when frozen) leaves the orb and panels capturable. Settings "Orb follows the task" (`orb_flight`, or `MISTAI_ORB_FLIGHT`; default off): after the task's first action the target is the window in front (re-checked right after each step and every 0.1 s for 2 s after it; browser_* steps use MistAI's Playwright Firefox window; never MistAI's own windows, the orb, panels, the taskbar/shell or Task Manager; the window that was in front before the task only if it is the app the step opened or switched to) and the orb flies an upward arc to `orb_layout.dock_position` (right of the target, then left, above, below; never over it when a side fits; inside that monitor's work area) and goes small; a target covering 90%+ of its work area docks inside it with `dock_inside`, beside the element the step's click touched (`last_element_rect` on the click handler / UIA navigator) or at the middle of the nearest inner edge (never a corner); a docked arrival dwells 1.5 s (`DWELL_S`) unless stopped; after a successful browser_search it tours up to 4 result links (`BrowserSession.link_boxes` via `page.evaluate`: up to 12 de-duplicated candidates with hidden/ad flags, numbers only; `orb_layout.classify_page_rects` keeps the first 4 visible non-ad ones centred in the viewport, logs `tour candidates found/measured/accepted/rejected` with reason labels, re-reads once after 0.4 s if fewer than 4 were found; any accepted rect outside the browser window = no tour), 0.7 s each in the page margin, choreography only (no steps or events), cancelled by the next `AgentStep`; on the final answer it flies medium to the left of the answer panel while `tts.speaking` (else a capped word-count estimate), then home; with no target it stays where it is; the chosen target is logged as numbers and a reason label; it is click-through (`WS_EX_LAYERED|WS_EX_TRANSPARENT`) while the agent runs, then speaks medium and flies home big. Settings "Task panels" (`orb_panels`, or `MISTAI_ORB_PANELS`; default off; needs the orb shown): `core/floating_orb.py` opens three windows hardened like the orb and listed in its `handles()` (so OCR masking and the input refusal cover them): a steps list (`label_for`: a label from the tool's categories, e.g. Clicking, Typing, Reading the screen, Running a command; ticked from `ActionExecuted`/`ActionFailed`) and the answer, fed by the bus event `AgentStep` (`AgentLoop._publish_step`, never logged), anchored at the top of the target's monitor (else the primary) by `orb_layout.anchored_panels` (`MISTAI_PANEL_ANCHOR` = top-right (default) | top-center | top-left; 16 px inset, 12 px gap; a non-maximized target covering the stack moves it to the next anchor; never over the orb), sliding in from above, each with a close (`PanelBridge`: `panel_state`, `dismiss`), closing `ANSWER_S` (8 s) after the answer's speech ends and at once on TaskFailed/TaskPaused, a stop, or `AgentStep` "failed" (agent call failed / network sentence), when the orb also goes home. `MISTAI_PANEL_BLUR` (default off) tries the Windows 11 DWM backdrop; the log says `panel style: blur|plain` once (plain = a rounded region). Pure geometry, tested heavily: the ORB LAYOUT GEOMETRY sections of `core/floating_orb.py`. Floating orb states (`orb_state(api, signals, docked)`, first match wins): listening > waiting > speaking > error (6 s) / completed (2.5 s, both from the end of speech) > reading > planning > executing (an action running, or docked) > thinking > idle; big for idle/listening, small docked (medium there for waiting/reading), else medium. They come from content-free bus signals (`events.ORB_SIGNAL`, never logged, published only while the orb is shown): `started`/`finished` (outcome + reason label) in `PlanRunner.run_goal`/`resume` for every task, one-node ones too (which still emit no Task* events); `planning` around make_plan's `_llm`; `reading` around UIA/vision screen context and `analyze_screen`/`read_screen_text`; `waiting` in `ask_confirmation` and ask_user (question text only with Task panels on). All looks are CSS in `ORB_HTML` (`data-state`; `data-motion="still"` when Windows animation effects are off, like reduced motion). Panels add display-only `waiting` (question + hint) and `error` (`ERROR_REASONS` sentence) kinds (`STATUS_KINDS`, no buttons; `dismiss` refuses them). `Api` (`core/api.py`, very large) wires every subsystem together: wake-word loop (Google STT), TTS, and the `_act_*` action handlers; topic groups are mixin classes in the same file that it inherits (browser, system, window handlers). The mixin classes never read a name tests rebind on `core.api` (`wake_clips_enabled`, `recipient_match`, `_show_window_async`, `HEARTBEAT_SECONDS`); such methods stay on `Api` itself (`tests/test_api.py` (API STRUCTURE section)). Merged modules (api, floating_orb, config, planner, live_state, memory, screen, click_handler, caption, tts, workspace, executor) start with a SECTION INDEX; each section has a `# ====` / TITLE / `# ====` banner. A module reached through a module object keeps its old local name by an aliased import (`from . import live_state as clip`), and planner/executor/live_state import themselves that way.

**LLM backend.** All LLM calls go over HTTP to MistAI's own backend (`mist-ai.fly.dev` / `api.mistai.org`), not a provider SDK. `core/config.py` picks the URL and fallback (`APIKeyManager`) and holds the models, the only place they are chosen: `MODEL_CHOICES` `gemini` (Nova, `DEFAULT_MODEL`) and `mistral` (Flux), sent as the request's `"model"` field. There is no picker: `Api.current_model()` is always Nova (`Api._model_override`, set only by `live_checks --model`, is for testing), and a saved profile `model` row from the old picker is never read or written (left in place). Every router, planner, agent and hotkey call tries `model_chain(current_model())`: Nova (today's URL fallback, except a 429 skips it), then Flux once on the primary URL after an HTTP error (never after a timeout or network error), then the existing error path. `describe_api_error` names no model ("The service is busy right now (HTTP 429…). Try again in a moment." / "The service request failed (HTTP N…)."). Logs `[Label] Nova HTTP N, trying Flux`. Vision uses Cohere directly (`core/screen.py` `CohereVision`, `command-a-vision-07-2025`), never these ids.

**Request flow:** `Api.ask_mistai` → conversation layer → `PlanRunner` (`core/planner.py`) → `AgentLoop` (`core/agent.py`) → `Executor` (`core/executor.py`) → `Api._exec_sync` → `_act_*` handler.
- `ask_mistai` handles typed stop, "resume X" and the fixed filler replies first. Then, unless an agent is busy or a resume matched, `core/planner.py` `try_chat` makes one small `planner._llm` call that returns `{"route": "chat"|"task", "reply"}`. A chat reply skips the run gate, minimize, vision and planning, is stored with `memory.add_conversation`, and is spoken only in voice mode. Everything else goes to the agent unchanged. It logs `[Conversation] route=chat|task in X.XXs`, plus a label when the agent got it without a model decision: `(timeout|no reply|unparsable|no chat reply|error)` (read router latency and timeouts there).
- `make_plan` sends simple goals (and questions) straight to the agent with no planning call. Other goals become a small DAG of phases (`PlanNode`). A failed phase blocks only its descendants. Progress persists via `core/memory.py`, so tasks resume by name ("Mist, resume X").
- `AgentLoop._loop` runs one phase step by step. The model returns one JSON object per step (`{"action", "parameter", "speech", "thinking"}`) parsed by `_parse_cmd` (malformed JSON → `parse_retry`). With `MISTAI_BATCH_STEPS` (default on) a reply may instead carry `"steps"`: 2-4 of `open_app`/`switch_app`/`type_text`/`press_key`/`hotkey` (`config.BATCHABLE_ACTIONS`); the steps form is shown in RESPONSE FORMAT (the prompt's last block) and the closing message asks for "one action, or a steps list"; a bare JSON array of such steps counts as a batch. Every reply logs `[Reply] shape=object|steps|array of N|text|...` (content-free). Steps 2+ skip the screen read and the model call but run the same loop body (guards, confirmation and Enter rules, `Executor.run`, observation). The rest is dropped (an observation lists it) after any failure, refusal, No, or when the phase's app left the front. A partly bad list (steps object or bare array) runs its longest batchable prefix of 2+, else its first step alone as a single action (every gate unchanged); the steps after it never run and `BATCH_DROP_NOTE` tells the model which and why once the run part ends. Only a list with no usable first step is a `parse_retry` with `BATCH_RETRY_NOTE` naming the reason; the log says `[Batch] malformed steps list (<label>) -- running N of M steps | parse retry` (labels: not-json, not-objects, too-few, too-many, missing-field, bad-parameter, mixed-form, non-batchable-action <menu id or unknown>). `_build_system` builds the prompt: action menu, `WORKSPACE` context, screen context, known folders, recent conversation.
- `Executor.run` is the single execution path: it reroutes UIA actions to OCR when a browser has focus, calls `_exec_sync`, waits the tool's settle time, runs the ground-truth verifier, scores confidence, and escalates to `fallback_tools`. Handlers report detail text via `api.last_result_text`.

**Adding or changing an action touches three places:**
1. `core/tools.py`: a `_T(...)` `ToolSpec` in `SPECS` (settle, confidence, destructive/confirmation flags, fallbacks, `verifier`, and `result_chars`) and its `_PLAYBOOK` entry (`purpose`: the one menu line; `args`: the exact parameter format, separators verbatim; `limits`; optional `example`; optionally an `_ARG_RX` structural check). The prompt's AVAILABLE ACTIONS list is generated from it (`action_menu`), one line per action; `describe_action` returns the full entry; `tests/test_agent.py` (ACTION PLAYBOOK section) fails when SPECS, the dispatch and the menu drift apart.
2. `core/api.py` `_exec_sync`: the `elif action == ...` dispatch to an `_act_*` method (the method may live in one of api.py's mixin classes).
3. `core/executor.py` `VERIFIERS`: optional ground-truth check.
Rules that concern more than one action stay in `core/agent.py` `_build_system`. An unknown action name gets the closest names and the best match's entry; a parameter failing its `_ARG_RX` still runs, and its observation carries the entry.

**Safety gates.** `ToolRegistry.is_destructive` / `requires_confirmation` and `command_is_mutating` decide when `AgentLoop` must ask the user. Both it and the planner ask through `Api.ask_confirmation`: the chat shows the question with Yes/No buttons (a click beats a spoken answer; voice mode also listens), an unclear answer gets one retry, then the phase ends (fail closed). `press_key` Enter/Return asks unless `Api.enter_target_is_safe()`: the app this phase opened or switched to is in front and is not a browser, messaging, mail or terminal app (`ENTER_CONFIRM_APPS`) or MistAI itself; Delete always asks. Regression tests pin this: run them after touching the agent, tools, or wake-word matching.

**Browser.** `core/browser_session.py` drives a dedicated persistent Playwright Firefox profile (`~/MistAI/browser_profile_from_daily`, seeded from the user's Firefox on first launch) through the DOM (`browser_*`). OCR/UIA clicking (`core/click_handler.py`, with the UIA navigator) is for native apps and the last resort inside browsers. A failed start never sticks: a start that timed out gets one more wait on the next call, a crashed one starts again. `open_app` caches Start-apps AppIDs per session (hits only); a cached ID that brings no window is looked up again once.

**Background state.** `core/live_state.py` holds the event bus with one dispatch thread (subscribers must be fast), the clipboard owner, and the watchers that bridge `LiveState` (foreground window, clipboard, processes) and file changes into events. `LiveStateTracker` owns a WinEvent hook (`WinEventHook`: SetWinEventHook out of context on its own daemon thread with a message loop; foreground, top-level create/destroy/show/hide, title changes) feeding `WindowEvents` (foreground hwnd + pid, a 64-event ring, no titles; own-process events are not "relevant"); a foreground event re-polls at once and StateWatcher wakes on events. `settle()` ends a `ToolSpec.settle` early only after `settle_floor` (`tools.SETTLE_FLOORS`), with the expected window in front (the opened/switched app, MistAI's browser window after navigation, else any) and 0.15 s without relevant events, else the full settle; the loop's 0.2 s step pause likewise (floor 0.05). Any failure (hook not installed, thread dead, no events, the 1 s poll seeing a foreground the hook never reported) = the old fixed waits, logged once. Logs: `[WindowWatch] settle 0.31s (cap 1.50s, window+quiet)`. Persistent data lives in `~/MistAI/memory.db`.

## Agent behavior (what the tests pin)

- **Result sizes.** The agent cuts each observation to its tool's `result_chars` (default 300; 4000 for read tools such as `run_command`, `browser_get_text`, `inspect_file`, `find_file`) and appends `[truncated, N more chars]`. Only the two most recent READ results (`result_chars >= 4000`) stay in full; older ones shrink to 300 before the history is resent.
- **Screen context.** `MISTAI_VISION_GATING` (default **on**; `0` disables): the screen is re-read only after UI-changing actions, when the foreground window changes, or after 30s unless nothing changed: with healthy window events, the same foreground window (hwnd + title hash), the same Open apps, no relevant window event since and an identical full-resolution frame hash, the cache is reused (`[Screen] unchanged since last read (no events, same frame), reuse`), else `re-read: cache expired (<reason>)`. `MISTAI_LAZY_VISION` (default **2**: a phase's first read is title + Open apps only; `1` = title + Open apps + a UIA summary capped at 1.5s; `0` = vision, the old default). The model can call `analyze_screen` / `read_screen_text` when it needs pixels; those answer only from what is visible (transcribed, never computed) or reply `NOT VISIBLE ON SCREEN`. In native (non-browser) windows `read_screen_text` reads the exact accessibility-tree text first (`core/screen.py`, 1.5s budget, 300 chars). With `MISTAI_UIA_FIRST` (default on), text that is sufficient (`text_is_sufficient`: non-empty, more than the window title, not cut at the cap) answers alone, with no vision call, unless the question is visual or empty (`is_visual_question`: colours, images, layout...). The non-lazy per-step screen context does the same for the foreground native window (`AgentLoop._exact_text_context`). Otherwise vision answers with the text beside it and a NOTE when vision reports numbers that text lacks: vision has reported results that were never displayed. The window read is the app the query names or the phase opened, even if it isn't in front; if only another window exists, its text is labelled as the foreground window, not the one asked about, never as exact. Vision reads take `WindowWatch.frame_for_read()` (`core/screen.py`; frames on demand, no capture loop, never saved): the last on-demand frame only if it was captured after the last non-read action or phase start (`mark_action`), else a fresh capture (about 20-30ms at 1080p); each read logs `[Frame] … old`. The UIA-first read reuses its last walk of a window (`[UIA] snapshot reused`) only while the same window shows the same frame with no UI action or relevant window event since; text under 8 chars is never kept. `MISTAI_TRACE_READS=1` (ignored in built apps) logs each read's vision answer next to that UIA text (text only, no images); the log lines contain on-screen text, so skim before sharing.
- **Grounding rules** live in `_build_system` and `planner._PLAN_PROMPT`, pinned by `tests/test_agent.py` (GROUNDING RULES section): facts about the machine come from the Open apps list or commands (`Get-Process`, `Test-Path`), never from screen reads; "done" means the question was answered; never state unseen data or write placeholder content; if the task was done by a different route than asked, say so; the planner plans only what remains and delivers only what was asked (a question's deliverable is the spoken answer).
- **Secret guard** (`core/config.py`: `SECRET_FILE_PATTERNS`, `secret_file_in`, `secret_output_reason`). `run_command` still runs, but its output is withheld (exit status kept) if the command references a secret-pattern file (`.env*`, `*.pem`, `*.key`, `id_rsa*`, ...), dumps or references secret-named env vars, or the output contains a private key block. `inspect_file` shows only name/size/hash for secret files and no content for binary files. The guard is not airtight: wildcards, piped listings, and runtime-built names get past it. `run_command` exit code 1 with no output is reported as "no results" (success), not a failure. Other nonzero exits stay failures.
- **Process matching.** Use `process_matches` / `is_self_process` (`core/config.py`), never substring checks. MistAI's own `msedgewebview2` and its own PID are excluded from app lists and window lookups.
- **Windows and input.** `window_belongs_to` (`core/live_state.py`) handles Store/UWP apps, whose windows belong to `ApplicationFrameHost` (a leftover frame matches by title); Open apps lists such frames too. The input target is the app this phase opened or switched to (`_last_opened_app`, reset at phase start). If that app is still not in front after one switch attempt, `type_text` / `press_key` / `hotkey` send nothing and fail with `NOT SENT`; otherwise they report which window got the input. With no known target, `type_text` only appends (no Ctrl+A/Delete), and no input goes to a terminal or MistAI's own console. `type_text` does not submit; the menu says to follow it with Enter. `press_key` sends one key: a combo (`ctrl+s`) or an unknown name is refused (`NOT SENT`, use `hotkey`), never forwarded past hotkey's confirmation list. A key in `config.DIALOG_KEYS` (or `alt+<letter>`, `opens_dialog`) ends its batch (`[Batch] cut after a dialog key`), and its observation carries a WINDOW CHECK: the foreground (hwnd, title) before vs after, polled briefly; new window / title changed / nothing appeared (+ "may not have taken effect" when the title keeps an unsaved marker); logged as a fixed label. `save_file_as(path)` (`core/api.py` SAVE AS DIALOG HANDLER) is the keyboard save: Ctrl+S (or a Save As dialog already open), a new window of the same process, the file-name Edit found through UIA by handle (`find_in_window`: name prefix "file name", else AutomationId 1001; looked for again every 0.1 s for up to `config.SAVE_NAME_BOX_WAIT_S` (3 s), since a new dialog is in front before its box is in the tree), Ctrl+A, the path typed once and read back, Enter, a replace prompt answered Yes only when the file existed before (the gate asked, like `write_file`), else No; success only when the file was written now; stops and says where otherwise; logs `[SaveAs]` labels. In the file dialog this phase's own `FILE_DIALOG_KEYS` key or `save_file_as` call opened (same pid, class `#32770`; also one save_file_as stopped in), `press_key` Enter/Escape, and Delete while focus is in an Edit, skip confirmation (`[Confirm] not asked: ...`); everywhere else, the replace prompt included, the gate is unchanged. At `done`, an absolute path this phase passed to `save_file_as` / `write_file` must hold a file (dropped after `move_files`, `organize_desktop` or a mutating `run_command`): one FILE CHECK reminder, then the phase fails with `FILE_NOT_SAVED_SPEECH`. Click marker (`core/caption.py` `ClickIndicator`): one persistent window made inert while hidden (`make_inert`: WS_EX_NOACTIVATE|TRANSPARENT|TOOLWINDOW|LAYERED; the caption overlay too), shown only AFTER every click (`_execute_click`, `click_coords`, `uia_click`); `tools/repro_click_marker.py --yes` is the REAL-desktop check. `uia_click` acts through the element's UIA pattern (`activate_element`: Invoke, Toggle or SelectionItem, items Select first; a mouse click only without one; a failing pattern is never retried another way), then compares the window's accessibility tree before/after (`window_signature`); unchanged = still a success, method `UIA-unchanged` (confidence 0.5) and a result that says so. "The window in front" for reading (snapshot `foreground_window`/`foreground_hwnd`, UIA searches, screen text and identity) is `live_state.foreground_for_reading()`: never MistAI's own windows (this PID), the next non-MistAI window in z-order instead (`own_window_in_front`); input guards keep the real foreground. A 1-2 character click target matches only whole: OCR needs that exact word (`click_handler._ocr_score`, surrounding punctuation ignored; "52" is never "2"), `uia_click` matches the whole name and then, once, its spelled-out key name (`config.SPELLED_KEY_NAMES`: "Seven", "Plus", "Equals"...). `click_on_text` / `click_nth` / `click_coords` refuse points outside that app's window rect (+8px) and try the next method; there is no check when no target is known or its rect can't be read. Input actions may repeat (digits, keys), up to 3 identical calls in a row while the foreground stays the same. A `read_screen_text`/`analyze_screen` observation right after unsubmitted `type_text` says so (`UNSUBMITTED_READ_NOTE`). The first `done` of a phase gets one reminder (one extra model call) when its speech states numbers the last read doesn't show (only the EXACT UI TEXT counts when present), when that read followed typing that was never submitted, when input was refused or a fallback crossed tool categories, or when a `run_command` that `command_is_mutating` flags (failed ones too) has no later successful read-only `run_command`, `inspect_file` or `find_file` (`OBSERVE_ACTIONS`). The reminder says to finish an unfinished task, not report it; the second `done` finishes.
- **Clipboard.** All clipboard access goes through `core/live_state.py` (one lock; the watcher reads only when `GetClipboardSequenceNumber` changed; writes are our own moveable block (`_write_unicode`: private typed `kernel32`/`user32`, (units+1)*2 bytes with the NUL, unlocked before `SetClipboardData`, freed only on failure), never pywin32's `SetClipboardData` with a str (pywin32 311 takes a digit string such as "37" as a HANDLE: heap corruption 0xC0000374; repro `tools/repro_clipboard_crash.py`, a REAL desktop run); open, empty and close are pywin32, `OpenClipboard` retried after `OPEN_RETRY_DELAYS` (10/20/40 ms), the clipboard always closed once opened; the helpers' raw calls use a private typed `user32` (`_user32()`), never the shared `ctypes.windll`). `type_text` retries a busy clipboard for 1.5 s with jitter, logs `[TypeText] clipboard busy holder=self|other|unknown`, then types text of up to 200 chars with no newline as SendInput Unicode events (reported in the result); longer text fails with the field untouched. It restores the previous plain-text clipboard. A failed write logs `busy` (could not open) or `denied` (opened, write refused) with the holder and Win32 code. Circuit breaker (`live_state.Breaker`, per Api): after 2 type_text calls in 60 s fail to stage, short one-line text goes straight to key events for 60 s (same input-target guard and limits; longer text still tries the clipboard and fails closed); a successful write closes it.
- **Paths.** Use `{desktop}`, `{documents}`, `{downloads}`, `{home}` placeholders or the Known folders line in the prompt; Desktop and Documents may be OneDrive-redirected.
- **`find_file`** is a real filesystem search (`core/workspace.py`): workspace root, Desktop, Documents, Downloads, then home; skips `node_modules`, `.git`, venvs, build/cache folders; exact-name matches rank first.

## Scenario harness

`tools/run_scenarios.py` + `tools/scenarios.json` run scripted scenarios through the real `Api.ask_mistai`.

```bash
python tools/run_scenarios.py --stub --compare --yes     # safe: scripted LLM, no network, vision off
python tools/run_scenarios.py --compare --allow-ui-input --yes   # REAL run (see below)
```

- Modes: `baseline`, `gating`, `gating+lazy2` (`--compare` runs these three; `--mode gating+lazy1` still works; `--repeat N` repeats runs and adds a min/median/max timing table). Plan-only scenarios call `make_plan` and assert the node list.
- `--tag NAME` runs only scenarios tagged NAME. The `realistic` tier (13 everyday requests after the original 11: files, then browser, then Notepad) runs only with `--tag realistic` or `--only <name>` and is left out of plain runs entirely. `needs: ["network","browser"]` SKIPs in `--stub` with the reason. Setup `serve_tmp` serves the scenario's tmp folder on 127.0.0.1 (free port) as `{tmp_url}` and stops it afterwards; `file_contains` reads files as UTF-8 (BOM and CRLF tolerated). `tests/test_harness.py` pins a hash of the original 11.
- A **real** run uses the real backend and sends screenshots to Cohere, and `--allow-ui-input` types into windows. Close Notepad, Calculator, and anything private first, and don't touch mouse or keyboard while it runs. Only run it when the user explicitly asks.
- Notepad scenarios skip themselves if Windows 11 Notepad restores leftover tabs. A scenario that opens an app skips if a window of that app (including a leftover UWP frame) is already open; after cleanup the harness closes windows of its own that linger. It never deletes Notepad state, removes only its own `%TEMP%\mist_scn_*` folders and processes it started, and warns when run elevated (run it from a normal shell).
- `tools/live_checks.py` (checks in `tools/live_checks.json`) automates the live checklist on top of this harness: `--stub` (default: the real Api class with its OS layer faked, scripted model; what pytest runs) or `--live --yes` (either laptop; refuses an elevated shell unless `--allow-elevated`). Message checks also need `--allow-send` and the gitignored `tools/live_checks.local.json` (`send_app`, `send_contact`, `wrong_contact`, optional `close_contact`); bodies are `mist-check-<random>`. Each check gets a temp database, a `mist_live_*` folder and an action allowlist; it is PASS/WARN/FAIL/SKIP, or INFRA (failed only on timeouts, HTTP 5xx/429 or the network sentence, with no safety violation: retried once after 20 s, listed first, exit code unaffected), and the human-only items are listed as MANUAL. scrub/injection-note judge the payloads that reached the backend, whichever tool the model used. `--model <id|label>` A/Bs models through the temp profile. `~/MistAI/logs/live-checks-<timestamp>/summary.md` copies only allowlisted, content-free log lines (MISTAI_VERBOSE_LOGS is unset for the run).
- A FAIL/TIMEOUT/ERROR whose log shows only backend or network errors (the same `INFRA_LINES` live_checks uses, or the network sentence) and no safety failure is INFRA: listed with a note, exit code unaffected.
- Real runs send one background GET to `STATUS_URL` before the first scenario (`[Harness] warm-up status N in Xs`); stub runs never do. The app itself has no such call. Output goes to `~/MistAI/logs/scenarios-<timestamp>/` (`summary.txt`, `summary.json`, one log per run). Logs are content-free unless `MISTAI_VERBOSE_LOGS=1`; the harness sets it for its runs (each log's first line says so), and the flag is ignored in built apps. Skim logs before sharing either way.

## Gotchas

- The conversation router fails closed: any error, timeout, unparsable or doubtful reply routes to the agent. It calls `planner._llm` through the module attribute, so the `--stub` fence covers it (in stub runs every turn logs `route=task`). Its routing rules live only in `conversation._PROMPT`, pinned by `tests/test_planner.py` (CONVERSATION ROUTER section); there are no phrase lists.
- Only the Python `minimize_window()` in `ask_mistai` (agent path, after the run gate) minimizes MistAI. JS `send()` no longer does, so chat, filler and busy replies stay visible.
- `handtracking/` was moved out of the repo (separate MediaPipe experiment). The app doesn't use it.
- Tesseract (`MistAI_OCREngine/`, ~83 MB) is tracked on purpose because `MistAI.spec` bundles it; moving it to a CI download step is a separate task.
- Windows 11 Notepad restores unsaved tabs from its `TabState` folder; a "fresh" Notepad may not be empty.
- The old docs website (`docs.html` etc.) was removed; user docs live on the main MistAI web site. In the repo: README.MD (overview, limits, safety model) and docs/ARCHITECTURE.md (how the pieces fit).
